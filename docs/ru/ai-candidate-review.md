# Проверка AI-кандидата перед принятием

[Документация](index.md) · [English](../en/ai-candidate-review.md) · [AI](ai.md) · [Команды](command-api.md)

В нативном приложении ответ AI с CAD IR v2 открывает отдельное окно «Проверка AI-кандидата». Оно показывает предлагаемую геометрию и сравнение с ревизией, на которой был отправлен запрос. Проверка обязательна даже при отключённых обычных подтверждениях: ответ ассистента сам по себе не сохраняет новую модель.

## Действия пользователя

1. Отправьте запрос ассистенту. После проверки ответа ядром CAD дождитесь построения предпросмотра в окне кандидата. До готовности кнопка «Принять кандидат» недоступна.
2. Вращайте модель левой кнопкой мыши, перемещайте правой, масштабируйте колесом. Кнопка вписывания плавно возвращает модель в окно; режим уменьшенного движения отключает переход.
3. Переключайте «AI-кандидат» и «Текущая модель». Текущая модель загружается из GLB исходной ревизии отдельным объектом. Основная сцена проекта не переносится и не изменяется. Если исходного GLB нет, интерфейс сообщает об этом; кандидат остаётся доступен для просмотра.
4. Сравните параметры, операции и тела. Значения параметров показываются до/после; изменения операции, подавления, порядка и имени отмечаются отдельно. Подробное сравнение и исходный код раскрываются с анимацией при каждом открытии и закрытии.
5. «Принять кандидат» запускает существующий маршрут построения и сохранения одной ревизии. «Отклонить кандидат», крестик, Escape и закрытие окна отменяют просмотр. Исходная модель и история остаются прежними; переписка ассистента сохраняется по обычным правилам проекта.

Если проект или его текущая ревизия изменились, принятие блокируется. Отклоните кандидат и повторите запрос на актуальной модели. При ошибке геометрии доступен повторный предпросмотр и техническая причина; ошибочный результат нельзя принять.

## Технический маршрут и хранение

`App` захватывает снимок проекта на отправке запроса. `agents/repair` проверяет ответ и максимум две попытки исправления. Для нативного CAD-документа `ActionReviewDialog` монтирует самостоятельный модуль `features/agents/review`. Структурное сравнение использует стабильные идентификаторы параметров/операций/тел; порядок ключей JSON не считается изменением, порядок массивов учитывается.

`useModelPreview` вызывает `preview_model` с ID исходного проекта, ожидаемой ревизией и неизменяемым кодом кандидата. Worker строит BREP/GLB во временном рабочем пространстве. Бинарный пакет ограничен по размеру и проверяется по SHA-256 исходного кода. Предпросмотр не создаёт ревизии, STEP в экспорте или проектные вложения и не расходует разрешение на изменение. При закрытии запрос отменяется, отдельные объекты Three.js освобождаются; поздний результат не возвращает закрытое окно.

Перед принятием повторно проверяются ID проекта и ревизия. Когда настройки требуют разрешение `modify_project`, одноразовое разрешение запрашивается и разрешается только в момент решения, а не до длительного просмотра. При отключённом подтверждении backend использует прежнюю автоматическую запись аудита; явное решение в окне кандидата всё равно требуется. Отказ регистрируется через существующий маршрут разрешений. Далее `apply_program` выполняет повторную проверку и сохраняет одну ревизию обычным транзакционным маршрутом. Новых SQL-таблиц нет; состояние сравнения временное и не сохраняется как новая модель.

## Ограничения и проверка

Сравнение структурное, а не оценка геометрического совпадения. Показаны точные метрики **кандидата**; переключение вида не превращает их в метрики исходной модели. Для STEP/mesh-импорта или старого CadQuery без CAD IR структура исходника недоступна. Старый маршрут CadQuery сохраняет прежний диалог подтверждения. Просмотр не накладывает модели друг на друга и не синхронизирует две камеры: переключение происходит в одной сцене с плавным вписыванием.

На этом этапе геометрия строится для проверки ответа, отдельно для интерактивного предпросмотра и повторно при применении. Результат предпросмотра не используется как доверенный сохранённый артефакт. При закрытии приложения непринятый кандидат не восстанавливается автоматически. Принятие входит в общий транзакционный undo/redo; остальные критерии 2.0 проверяются отдельно.

## Структурированный план

Поле `reviewPlan` содержит допущения, предложенные размеры с необязательным `parameterId`, ID затронутых тел и ожидаемые проверки. Карточка использует раскрытия редактора и библиотечные иконки. Размеры без ссылки на параметр остаются утверждениями AI. Пределы: 16 допущений по 400 символов, 32 размера, 32 уникальных ID тел и 16 проверок.

Проверки `validSolid`, `bodyCount`, `bounds` и `volume` сравниваются с точной геометрией кандидата. `bodyCount` считает объявленные тела CAD IR: импортированная STEP-сборка одним составным телом считается одним телом. Габариты и объём проверяются с заданным допуском без скрытой добавки. До построения виден статус ожидания; несовпадение блокирует принятие. Backend повторяет проверки по свежему worker-результату перед commit, проверяет ссылки тел и значения именованных параметров. Ошибка не сохраняет ревизию.

Маршрут: `plan_model` → строгая проверка контракта → `CandidatePlan` и проверенный preview → явное решение → `apply_program` с исходным планом → независимое построение и проверки → одна ревизия. При допустимой геометрической ошибке AI получает максимум две попытки исправления с той же сохранённой базы и исходными требованиями. Изменение плана не считается исправлением. Отмена, конфликт доступа или потерянная ссылка не запускают эти попытки.

Провайдер без плана совместим; окно явно сообщает об отсутствии структурированного плана. Допущения и результаты проверок пока временные, без отдельного долговечного отчёта ревизии. Параметры и принятая модель сохраняются обычным маршрутом. Проверка: unit-тесты контракта и метрик, native-тест неверного ожидаемого объёма без commit, Chromium RU/EN с реальной GLB, успешными проверками и блокировкой неверного объёма.

Проверка: unit-тесты сравнения, принятия/отказа и освобождения моделей; Chromium-сценарии с GLB настоящего локального worker, RU/EN, светлой/тёмной темой, узким окном, повторным раскрытием и сменой проекта. Внешний авторизованный CLI и установленный WebView2 этим набором не проверяются. Реальные проекты пользователя не используются тестами.

## Единый интерфейс с редактором модели

Рамка, прокрутка, нижняя панель и код используют общий `features/model-editor/EditorDialog.css`. Заголовки кода и подробного сравнения — тот же `EditorDisclosure`, что в редакторе; параметры имеют его карточку и иконку SlidersHorizontal. Операции используют существующий FeatureIcon. Открытие окна — 200 мс, закрытие — 140 мс; раскрытие содержимого и поворот стрелки — 260 мс с тем же easing. Содержимое сохраняется до завершения закрытия, поэтому окно не переключается на общий диалог разрешения во время исчезновения. Уменьшенное движение отключает анимации. Временные раскрытия кандидата не перезаписывают SQLite-настройки редактора.
