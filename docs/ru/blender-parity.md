# Подготовка переноса приёмов Blender

[Документация](index.md) · [English](../en/blender-parity.md) · [Наблюдения](../parity/blender/README.md) · [Аудит готовности](../parity/blender/readiness.md)

Этот раздел описывает исследовательский этап M0. Он не добавляет инструменты в установленную FormaCAD. Перенос выполняется собственной реализацией на TypeScript/React, Rust и C++/OCCT, с сохранением точной B-Rep-модели и существующего Command API. Общие границы и критерии выпуска заданы [архитектурным планом](../architecture-2.0.md).

## Действия исполнителя

Прочитайте [правила совместной работы](collaboration.md), актуальный [статус](status.md) и назначенную Issue. Подтвердите ответственного человека и владельцев путей. Работайте в отдельной ветке/worktree от проверенного main; существующие локальные файлы не переносите и не удаляйте ради чистого дерева. Текущая задача — [M0 #17](https://github.com/lovlyDev/FormaCAD/issues/17).

Запускайте собственные зонды Blender с фабричным стартом, фиксируйте точную версию и build hash. Для фонового зонда задавайте `--python-exit-code 1`: обычное завершение Blender не гарантирует успех Python-скрипта. Проверяйте наличие результата и assertions. Для живой раскладки дождитесь инициализации GUI в отдельном процессе и закройте только этот процесс. Не сохраняйте тестовую сцену поверх пользовательского файла.

Заметки пишите своими словами по схеме: источник → наблюдение → решение FormaCAD → модуль → статус и проверка. Не переносите исходники, декомпиляцию, ресурсы, тексты руководства, файлы тем и раскладок Blender. Необязательные обращения к исходникам должны иметь отдельное обоснование и журнал; в данном исследовании таких обращений нет.

## Технический маршрут и хранение

Blender CLI/Python и REA используются только при разработке. Факты и собственные зонды находятся в игнорируемой `.local/m0-preflight/`, переносимый Node — в её `tools/`, REA — в `rea/`. Эти файлы не входят в приложение, Git и пользовательский проект. Версионируемые заметки находятся в `docs/parity/blender/`; в них нет сырых таблиц раскладки или содержимого моделей пользователя.

Для последующей функции маршрут остаётся `React → typed IPC → Rust Command API → staged CAD IR → отдельный worker → OCCT → валидация → commit`. Наблюдение Blender не даёт плагину или UI обходного пути к геометрии. Изменение только вида не должно создавать геометрическую ревизию. Внешние зависимости SDK и инструменты исследования не делают Python обязательным runtime CAD.

## Окружение и ограничения

В исследовании использованы Blender 5.2.3 LTS (`e13b728c6880`), Node 24.22.1 в отдельной локальной папке, REA 6.8.0 через CLI, Rust 1.97.1, MSVC 14.51 и Windows SDK 10.0.26100.0. CMake 4.3.1-msvc1 и Ninja 1.13.2 доступны в составе Build Tools, но отсутствуют в обычном PATH; путь нужно задавать процессу сборки. Не подменяйте это утверждением, что любой терминал уже настроен.

REA применён без декомпиляции. План регистрации MCP просмотрен без применения; работа CLI не означает, что новый MCP уже подключён в этом чате. Ghidra для выполненных наблюдений не требовался. SDK TypeScript/Python и их упаковщики относятся к реализации SDK; в runtime FormaCAD они не добавлены.

Для закреплённого toolchain 1.97.1 подготовлены обе цели `wasm32-unknown-unknown` и `wasm32-wasip2`. Отдельно в `.local` распакованы официальные Windows CLI wasm-tools 1.262.0 и wit-bindgen-cli 0.63.0; запуск `--version` проверен. SHA-256 архивов: Node — `D2046D28C2C3DCD211AC5145C0BF30E2047EF9DFB306693C8C6E2ECCD8B95FA5`, wasm-tools — `A39100CADAC426E174E449A80DB669F191B6A2E14F27C369553580CA6E9EA7E3`, wit-bindgen — `213393E4A8B4875A3F19856E943E43067D0315141FCA5743E4CFB7795BC9AF14`. Node дополнительно сверён с официальным SHASUMS256; для двух Wasm-архивов это запись полученного хеша, а не независимая криптографическая аттестация. Эти инструменты не входят в зависимости приложения.

Дополнительно подготовлены отдельный локальный npm-пакет с jco 1.39.0 и componentize-js 0.23.0, а также Python virtualenv с componentize-py 0.25.1. Проверен запуск CLI; сборка SDK-примеров относится к M5. Chromium Playwright подготовлен в локальном кеше проекта. Эти сборочные инструменты не добавлены в workspace приложения.

Синтетический GUI-ввод, фоновые операции и интроспекция не заменяют ручную проверку интерфейса, геометрический паритет OCCT, производительность, установленный WebView и другие ОС. Условия конкретных проб, включая расширенный числовой ввод `=10mm`, описаны в тематических заметках. Не выдавайте их за готовые функции FormaCAD.

## Проверки перед передачей

Запускайте команды отдельно из корня нужного worktree:

```powershell
npm run check:version
npm run check:i18n
npm run check:docs
npm run check:migrations
npm run lint
npm run build
npm run test
cargo +1.97.1 fmt --manifest-path apps/desktop/src-tauri/Cargo.toml --check
cargo +1.97.1 clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --locked -j 2 --all-targets -- -D warnings
cargo +1.97.1 test --manifest-path apps/desktop/src-tauri/Cargo.toml --locked -j 2 --lib
```

Для Rust предварительно подготовьте MSVC/SDK через существующий `scripts/windows-env.ps1`. При изменении ядра дополнительно нужны CTest и native worker tests; при изменении UI — e2e RU/EN и обе темы. В M0 приложение не меняется: новый номер версии и установщик не создаются. Задача приложения считается готовой только после своих проверок, документации и приёмки; исследовательская заметка этого не заменяет.
