# Типизированные правки модели

[Документация](index.md) · [English](../en/command-api.md) · [AI](ai.md) · [Эскизы](sketches.md)

В локальной 1.2.6 AI может предложить небольшой список команд вместо полного переписывания CAD-документа. Например: «Увеличь width до 80 мм и отвяжи X точки a, сохранив её положение». Команды применяются к снимку текущей CAD IR v2 ревизии, проходят валидацию и проверку BREP. После подтверждения сохраняется одна новая ревизия; промежуточные команды не записываются. Существующий UI подтверждения показывает итоговый CAD-документ, а не отдельный интерактивный список команд.

## Формат предложения

```json
{"message":"Изменить ширину и снять связь","expectedRevision":"draft","commands":[{"command":"set_parameter","parameterId":"width","valueMm":80},{"command":"remove_sketch_binding","featureId":"base_sketch","bindingId":"a_x"}]}
```

`expectedRevision` должен совпадать с `currentProgram.revisionId`. Допускаются 1–256 команд и только известные поля. `commands` несовместим с `cad`/`program`; неизвестные команды и лишние поля отклоняются. Новый проект, импортная STEP/сетка и документ без CAD IR v2 не являются базой команд: агент возвращает поддерживаемый полный `cad` либо уточнение `program:null`. Codex, Claude и Custom CLI используют одну проверку ответа.

## Команды координатных связей

| Команда | Поля | Результат |
|---|---|---|
| `add_sketch_binding` | `featureId`, `binding` | Добавляет новую явную связь; дубликат ID или оси отклоняется |
| `set_sketch_binding` | `featureId`, `binding` | Заменяет существующую связь с тем же ID; неизвестный ID отклоняется |
| `remove_sketch_binding` | `featureId`, `bindingId` | Сохраняет текущую эффективную координату выбранной оси и снимает её связь |

`binding` имеет форму `{"id":"a_x","target":"point","pointId":"a","axis":"x","value":{"kind":"parameter","parameterId":"width","scale":-0.5,"offsetMm":0}}`. Для начала плоскости используется `target:"origin"` без pointId, ось x/y/z; точка поддерживает x/y. Координата = параметр × scale + offsetMm. Связи и ограничения совместно ограничены 64 на эскиз; общие правила диапазонов и ссылок описаны в [эскизах](sketches.md). Автоматического привязывания соседних профилей и общего движка формул нет.

Команды выполняются по порядку: изменение width с 40 на 80 перед снятием a_x материализует -40 мм. Другие оси остаются связанными; последующее изменение width не перемещает отвязанную ось. Удаление связи не удаляет точку. Прямой set_sketch_point для связанной точки запрещён PARAMETER_BOUND; меняйте параметр, связь или сначала явно снимите связь. Для буквального размера используйте set_literal, для связанного — set_parameter.

## Маршрут и хранение

[AI parser](../../apps/desktop/src-tauri/src/agents/protocol/command_response.rs) читает строгий proposal; [Command API](../../apps/desktop/src-tauri/src/cad_ir/commands.rs) клонирует исходник, проверяет ревизию, выполняет пакет и валидирует результат. [Модуль связей](../../apps/desktop/src-tauri/src/cad_ir/commands/bindings.rs) при удалении разрешает текущие координаты тем же resolver, что диагностика/BREP. Ошибка любой команды возвращает код и targetId без изменения оригинала. Снятие связи материализует только её ось.

[AI session](../../apps/desktop/src-tauri/src/agents/session.rs) захватывает исходник и ревизию до запуска CLI; [repair](../../apps/desktop/src-tauri/src/agents/repair.rs) строит кандидат в отдельном worker. Результат поступает в прежнее подтверждение App. Перед apply_program повторно проверяется ревизия проекта; смена модели во время ответа отклоняет применение. Документ, STEP/GLB и ревизия сохраняются существующим маршрутом modeling/projects в SQLite и локальные артефакты. Источник сохраняет итоговые bindings, CADPACK переносит его; команды сами не экспортируют файлы и не исполняют код. Новая SQL-миграция не требуется.

Это основание транзакционного API, не завершённый план 2.0: интерактивный diff AI-кандидата, общий undo/redo и переносимое хранилище проекта остаются отдельными задачами. Полные cad-ответы совместимы; прежний CadQuery маршрут не принимает нативные command proposals. Реальные внешние аккаунты/CLI не требуются для контрактных тестов и не проверяются ими.

## Проверка

Проверить оба порядка «параметр → снятие связи» и сохранение независимых осей, origin, замену стабильного ID, устаревшую ревизию, неизвестную позднюю команду и дубликат цели. Ошибочный пакет должен сохранять исходный документ полностью. Контрактные тесты покрывают Codex/Claude/Custom, смешанные ответы и лимит 256. Нативный worker проверяет метрики изменённых связанных профилей и отсутствие скачка после снятия всех связей.

Снятие координатной связи не снимает независимые связи других размеров: если width также управляет длиной выдавливания, изменение width по-прежнему меняет эту длину. Для полного освобождения детали нужно явно изменить соответствующие размеры/связи, а не считать remove_sketch_binding командой «заморозить всё тело».

Перед добавлением ответа и подтверждением проверяются ID проекта и ревизия через [candidateSource](../../apps/desktop/src/features/agents/candidateSource.ts). Копия проекта может сохранять прежние ID ревизий, поэтому одного совпадения revisionId недостаточно: ответ исходного проекта не должен записываться или применяться в другом открытом проекте.

В примере draft соответствует [воспроизводимому документу связанных профилей](../fixtures/linked-profiles.cad.json). В сохранённом проекте вместо draft подставляется фактический ID текущей ревизии; это не универсальное значение.
