# M4 — инструменты моделирования II и данные

[Документация](index.md) · [English](../en/modeling-ii.md) · [План](../architecture-2.0.md)

Этап выполняется в task/m4-modeling-tools от main 8cb40fd (1.7.0-beta.1), по Issue #21. Реализованы первые модули — разделение тела плоскостью и утолщение выбранной грани. Это текущий результат, а не объявление готовности всего M4.

## Границы и последовательность

Отдельные модули: split, thicken, mirror features, offset profile, variable fillet, IGES, appearance/PBR/glTF, geometry table, history timeline, saved views и развитие smart selection. Каждая возможность проходит C++/Rust → Command API/staged-транзакцию → UI → RU/EN документацию → измерения, BREP-проверку и обмен.

Новые кнопки показываются после подключения рабочего маршрута. Изменения истории только явные, неоднозначные ссылки требуют ручного выбора. Хранилище и recovery Issues #27–#34 остаются в области wenlixxq.

## Разделение тела плоскостью

Откройте проект с доступным для изменения авторским телом. В меню «Инструменты» выберите «Разделить тело плоскостью». Укажите тело (имя и полный ID), ось нормали X/Y/Z и смещение плоскости в миллиметрах. Если тел несколько и ничего не выделено, требуется явный выбор. Проверьте предпросмотр и нажмите «Построить», затем подтвердите разрешение.

Исходное тело сохраняет положительную часть относительно нормали. Новое тело с суффиксом (-) получает отрицательную часть. Обе части записываются одной ревизией; исходные операции остаются в документе как зависимости. Отмена диалога не меняет проект. Undo/redo выполняются явно стандартными кнопками истории; сохранённая ревизия разделения не удаляется.

Маршрут: features/split → apply_ir_commands → staged clone с проверкой expectedRevision → cad_ir::SplitPlane → native/split → cad-core/src/split.cpp → OCCT Common с двумя полупространствами. Каждая часть проходит BREP-проверку и проверку положительных конечных измерений; сумма объёмов должна совпадать с исходным объёмом. Стороны заданы явно, а не порядком перебора топологии.

Команды создают две операции SplitPlane, меняют источник исходного тела и добавляют второе тело атомарно. Сохраняется обычный CAD-документ в существующем формате проекта, без миграции хранилища. Неудача проверки не публикует staged-состояние. Пустое число, нечисловые координаты, нулевая нормаль, касание и промах плоскостью отклоняются. Пользователь получает переведённую ошибку; технический код сохраняется.

Ограничения: UI задаёт плоскости по мировым осям; API поддерживает произвольную ненулевую нормаль. Привязка плоскости к выбранной грани здесь ещё не реализована. Части могут содержать несколько солидов для несвязного исходного тела. Автоматическая перепривязка старых ссылок на изменившуюся топологию не обещается. IGES-проверки относятся к отдельному будущему модулю.

### Геометрия и реальная проверка

C++: брусок 40×20×10 мм, плоскость X=5 → 3000 и 5000 мм³, размеры 15×20×10 и 25×20×10 мм; исходник остаётся 8000 мм³. Наклонная плоскость через центр даёт 4000 мм³. Цилиндр R10, H20 при Z=5 даёт 1500π и 500π мм³; полусфера R10 — 2000π/3 мм³ и 300π мм². STEP round-trip части сохраняет 3000 мм³. Касание, промах и некорректная нормаль проверены отдельно.

Транзакционный тест с настоящим worker проверяет откат при промахе, одну ревизию для двух частей и STEP round-trip сборки: 8000 мм³, 3200 мм², 12 граней, 24 ребра.

В собранном Windows-приложении с встроенным frontend проверены четыре сочетания RU/EN × светлая/тёмная тема. Подмены IPC нет: пользовательские действия проходят настоящий Tauri-хост и OCCT-worker. Тестовые проекты создаются через настоящие native-команды с разовыми разрешениями; само разделение выполняется кнопками UI. Подтверждены объёмы 3000/5000 мм³, общий объём 8000 мм³, площадь 3200 мм² и 12 граней. Промах и пустое число блокируют построение, ревизия сохраняется. Undo возвращает одно тело и площадь 2800 мм²; redo — два тела и 3200 мм². Три быстрых цикла предпросмотра и закрытие диалога не создают ревизию.

## Пустое пересечение: уточнение диагностики M3

При непересекающихся телах либо касании только гранью/ребром результат не является общим твёрдым телом. Ядро возвращает EMPTY_INTERSECTION; предпросмотр показывает «Пересечение пустое.», сохраняя технические подробности. Прочие ошибки объёма не переименовываются.

Путь: cad-core/src/booleans.cpp → native Shape/worker report → features/model-preview/previewError.ts → ru.json/en.json. «Построить» недоступна при неудачном предпросмотре. Ошибочная staged-команда оставляет прежний снимок неизменным. Нового состояния хранения нет.

C++ проверяет разнесённые тела, касание по грани и корректное самопересечение бруска 40×20×10 (8000 мм³). Rust проверяет код ошибки и откат; frontend — локализуемый ключ и подробности. В реальном UI во всех четырёх сочетаниях языка/темы два разнесённых тела суммарным объёмом 9000 мм³ дают понятную ошибку, не создавая ревизию.

## Стабильность предпросмотра

Нативная проверка обнаружила ошибку подключения событий Canvas после быстрого закрытия предпросмотра. Общий StableCanvas удерживает конкретный DOM-элемент для асинхронной инициализации React Three Fiber. Модуль используется в предпросмотре и основном viewport; исключения не подавляются. Отдельные тесты проверяют позднюю инициализацию после unmount. Повторная нативная матрица с быстрыми циклами прошла без ошибок JavaScript.

## Конфликт чтения после записи

Кодовый аудит 8cb40fd нашёл окно для list_projects/get: после SQL commit виден pending journal, пока writer ещё держит ProjectLock. Читатель reconcile может попытаться получить тот же немедленный writer-lock. Текущее inspect_model использует чистый snapshot; при pending возвращает PROJECT_SNAPSHOT_RECOVERY_REQUIRED, поэтому тот же writer-lock именно в inspect_model пока не воспроизведён.

[Диагностика](https://github.com/lovlyDev/FormaCAD/issues/32#issuecomment-6768465150) и [уточнение маршрута inspect_model](https://github.com/lovlyDev/FormaCAD/issues/32#issuecomment-6768476962) переданы владельцу Issue #32. Исходники хранилища не менялись; задержки и повторы для маскировки конфликта не добавлялись. Управляемое воспроизведение гонки и исправление остаются за владельцем хранилища.

## Оставшаяся приёмка

Остальные модули M4 ещё не реализованы и не проверены. Каждая новая геометрическая операция требует негативного случая, BREP-валидности, измерений, round-trip где применимо, отката транзакции и проверки через собранное приложение.

PR остаётся draft до завершения этапа. Версия, lockfile, установщик и релизы не изменяются.

## Повтор нативной приёмки split

Сценарий [split-native.mjs](../../scripts/acceptance/split-native.mjs) запускается отдельно от браузерных тестов с mock IPC. Соберите frontend и debug-host с native-worker-client и встроенными assets (TAURI_CONFIG с build.devUrl=null), а также worker с native-occt. Положите оба EXE рядом. Укажите отдельные пустые FORMA_DATA_DIR и WEBVIEW2_USER_DATA_FOLDER, доступные библиотеки OCCT в PATH и WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9336 --remote-debugging-address=127.0.0.1. Запустите этот экземпляр приложения и дождитесь стартовой панели.

В PowerShell из корня репозитория задайте $env:FORMA_NATIVE_ACCEPTANCE='isolated', затем выполните node scripts/acceptance/split-native.mjs http://127.0.0.1:9336 <абсолютный-путь-к-report.json>. Каталог отчёта должен существовать. Сценарий создаёт тестовые проекты, меняет язык/тему и оставляет отчёт со снимками. Его нельзя подключать к рабочему профилю пользователя. Пустые профили и отдельный экземпляр подготавливаются проверяющим; переменная isolated подтверждает эту подготовку и сама по себе не проверяет путь процесса.

### Указатель и стабильный источник событий

Стабильный источник событий — родитель холста. React Three Fiber по умолчанию отключает hit testing внутреннего контейнера при внешнем eventSource. В данном случае это мешало прямому наведению на canvas: указатель попадал в родителя, хотя холст уже был видимым и стабильным. StableCanvas явно сохраняет pointer-events: auto для внутреннего контейнера; события от холста всплывают к тому же стабильному родителю. Защита от поздней инициализации после закрытия остаётся действующей, пользовательские стили размеров сохраняются.

Регрессионная проверка охватывает hit testing и всплытие события, передачу стилей и позднее подключение после unmount. Исходные e2e persistence («workspace survives reload with camera, draft, hidden body and display mode») и workspace («viewport clicks and tools preserve camera zoom») сохраняют hover и таймаут 90000 мс; проверяются масштабирование колесом, переключение инструментов и восстановление камеры после перезагрузки. Формат сохранения камеры, геометрия и история проекта не меняются.

### Дополнение нативной проверки Canvas

После исправления hit testing собранное приложение прошло RU/EN × светлая/тёмная тема: 4/4, без ошибок JavaScript. Проверены наведение на основной и preview-холст, масштабирование колесом, объёмы split 3000/5000 мм³, undo/redo и отсутствие лишних ревизий. Повторяемый сценарий дожидается стабильной камеры, затем проверяет уменьшение расстояния до цели при прокрутке к модели.

Подготовка fixtures явно ждёт видимую миниатюру карточки проекта, подтверждающую завершение фоновой записи метаданных. Это не проверка немедленного read-after-write. До такого ожидания два чтения inspect_model завершились PROJECT_SNAPSHOT_CHANGED; попытка опрашивать list_projects во время записи миниатюры также воспроизвела «Project storage is locked by another writer». После завершения миниатюры тот же проект читается успешно: 8000 мм³, 2800 мм². [Наблюдения переданы владельцу хранилища](https://github.com/lovlyDev/FormaCAD/issues/32#issuecomment-6825300767); причинность без трассировки не объявляется доказанной. Продуктовых повторов ошибок, задержек или изменений storage нет; нативный сценарий не повторяет упавший IPC.

Локальные исходные persistence/workspace e2e: до правки 2/2 FAIL на hover, после — 2/2 PASS без изменения тестов. В первом полном локальном прогоне отдельно падал locked-pan EN; изолированный повтор взаимодействий дал 8/8 PASS, следующий полный прогон — 71 PASS и 89 штатных skip. Пропуски native-fixture браузерных тестов не считаются доказательством работы OCCT: для него выполнена отдельная матрица собранного приложения.

[Утолщение выбранной грани](thicken.md) — отдельный модуль M4; нативная матрица 4/4, исходное тело сохранено, новое тело 1600 мм³.
