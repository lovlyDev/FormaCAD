# M4 — инструменты моделирования II и данные

[Документация](index.md) · [English](../en/modeling-ii.md) · [План](../architecture-2.0.md)

Этап выполняется в task/m4-modeling-tools от main 8cb40fd (1.7.0-beta.1), по Issue #21. Это журнал текущей реализации и критериев приёмки, а не объявление готовности M4.

## Границы и последовательность

Отдельные модули: split, thicken, mirror features, offset profile, variable fillet, IGES, appearance/PBR/glTF, geometry table, history timeline, saved views и развитие smart selection. Каждая возможность проходит C++/Rust → Command API/staged-транзакцию → UI → RU/EN документацию → измерения, BREP-проверку и обмен.

Новые кнопки показываются после подключения рабочего маршрута. Изменения истории только явные, неоднозначные ссылки требуют ручного выбора. Хранилище и recovery Issues #27–#34 остаются в области wenlixxq.

## Пустое пересечение: уточнение диагностики M3

При непересекающихся телах либо касании только гранью/ребром результат не является общим твёрдым телом. Ядро возвращает отдельный код EMPTY_INTERSECTION; предпросмотр показывает «Пересечение пустое.», сохраняя технические подробности. Прочие ошибки объёма не переименовываются в пустое пересечение.

Путь: cad-core/src/booleans.cpp → native Shape/worker report → features/model-preview/previewError.ts → ru.json/en.json. «Построить» остаётся недоступной при неудачном предпросмотре. Если ошибочная команда дошла до staged-транзакции, прежняя ревизия должна сохраниться. Нового состояния хранения для этой диагностики нет.

Проверки C++ различают разнесённые тела, касание по грани и корректное самопересечение бруска 40×20×10: объём последнего 8000 мм³. Регрессия транзакции проверяет отказ с кодом и неизменность снимка; frontend проверяет локализуемый ключ и сохранение подробностей. Проверка через собранный UI/настоящий IPC ещё не выполнена; здесь она не объявляется успешной.

## Конфликт чтения после записи

Кодовый аудит 8cb40fd нашёл окно для list_projects/get: после SQL commit виден pending journal, пока writer ещё держит ProjectLock. Читатель reconcile может попытаться получить тот же немедленный writer-lock. Текущее inspect_model использует чистый snapshot; при pending возвращает PROJECT_SNAPSHOT_RECOVERY_REQUIRED, поэтому тот же writer-lock именно в inspect_model пока не воспроизведён.

Диагностика и отдельное уточнение переданы владельцу в [Issue #32](https://github.com/lovlyDev/FormaCAD/issues/32#issuecomment-6768465150). Исходники хранилища не менялись; задержки и повторы для маскировки конфликта не добавлялись.

## Оставшаяся приёмка

Каждая новая геометрическая операция требует негативного случая, BREP-валидности, конкретных измерений, STEP/IGES round-trip где применимо и отката транзакции. UI проверяется в русском/английском и обеих темах через собранное приложение с настоящим IPC, host и OCCT.

PR остаётся draft до завершения этапа. Версия, lockfile, установщик и релизы в этом этапе не изменяются.
