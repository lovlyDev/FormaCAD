# Паритет нативного моделирования и жёсткие преобразования

Реестр описывает практические сценарии геометрии: каждое имя метода CadQuery не считается отдельной пользовательской возможностью. Нативный CAD IR v2 пока не завершает объём 2.0. Совместимость Python сохраняется, пока для недостающих сценариев не появятся типизированные операции с проверенной геометрией.

## Текущая матрица

| Существующий сценарий | Нативное построение | Требуемый инвариант / регрессия | Состояние и ограничения |
| --- | --- | --- | --- |
| Пустой шаблон | Пустой документ | Не создавать выдуманное тело | Существующий маршрут |
| Блок / пластина | `rectangle` → `extrude`, необязательный `hole` | Ширина × глубина × высота минус цилиндрические отверстия; объём STEP | Существующий маршрут; отверстия направлены по мировой Z |
| Цилиндр / осевое отверстие | `circle` → `extrude`, `hole` | π(R² − r²)h; объём STEP | Существующий маршрут |
| Г-образный кронштейн | Выдавливания основания и стойки, перенос, объединение, отверстия | Связное тело, толщина стенки и габариты | Доступно из примитивов; сама эта матрица не заменяет полный эталонный тест шаблона |
| Открытый корпус | Внешнее выдавливание, перенесённое внутреннее выдавливание, вычитание | Толщина дна/стенок, открытый верх | Доступно через булевы операции; универсальной `shell` по выбранным граням нет |
| Сфера/конус и составная органическая фигура | Сфера/конус, перенос, объединение | Аналитический объём примитивов, корректный итоговый BREP | Примитивы проверены; произвольная органическая форма автоматически не выводится |
| Полигон с внутренними отверстиями | `sketch2d` со связями → `extrude` | Площадь решённого профиля × расстояние со знаком, рабочая плоскость | Существующий проверенный маршрут с линиями, вспомогательной геометрией и аффинными координатными связями |
| Прямоугольные зубья шестерни | Один зуб → перенос → явные `rotate` → объединения → центральное отверстие | Независимое интегрирование круга/прямоугольника; 51 × 51 × 8 мм; STEP | Новый тест преобразований воспроизводит legacy-фикстуру с 16 зубьями |
| Положение / поворот тела | `translate`, `rotate` | Сохранение объёма/площади, независимо рассчитанный AABB | Новые тесты произвольной оси и смещённого начала |
| Зеркальная копия асимметричного тела | `mirror` | Сохранение объёма/площади, положение проверено булевым пересечением | Новые тесты начала плоскости и наклонной нормали; копия не объединяется автоматически |
| Скругление/фаска всех рёбер | `fillet`, `chamfer` | Корректный BREP, уменьшение объёма, отказ при чрезмерном размере | Существующие ограниченные операции |
| Скругление выбранного ребра | `filletEdge` | Однозначное ребро блока при изменении параметров | Только селектор ребра блока; общей постоянной топологии нет |
| Импорт/экспорт STEP и mesh | Точное преобразование/измерение STEP, просмотр/экспорт mesh | Геометрия и единицы сохраняются | `importStep` — типизированный источник по хешу с нативными операциями поверх; сборка пока одним составным телом; mesh не становится BREP |
| Sweep, loft, shell; дуги/сплайны; twist extrusion; карманы/развёртки отверстий по грани; параметрические массивы | Полного типизированного маршрута нет | Корректные/вырожденные случаи, происхождение геометрии, STEP | Незакрытые критерии паритета; неподдерживаемый запрос не должен запускать сгенерированный Python |

Интерпретатор совместимости разрешает и другие имена методов в `model_program.py`. Разрешённое имя не доказывает поддержку всех аргументов/селекторов либо наличие нативной замены. Шесть фактических состояний шаблонов: пустой, блок, пластина, кронштейн, корпус, цилиндр. Преобразования не переписывают старые проекты молча: параметры шаблонов продолжают использовать существующий маршрут.

## Действия пользователя и типизированный контракт

Создайте модификатор через общую Command API: `add_feature` и `set_body_source` в одном пакете. Поворот задаётся так:

```json
{"type":"rotate","bodyFeatureId":"pad","axisOriginMm":[10,0,0],"axisDirection":[0,0,1],"angleDeg":90}
```

Зеркальная копия задаётся так:

```json
{"type":"mirror","bodyFeatureId":"rotation","planeOriginMm":[0,0,0],"planeNormal":[1,0,0]}
```

Направление/нормаль безразмерны, OCCT нормализует их. Начала задаются в миллиметрах мировой системы координат. Угол явно задан в градусах и никогда не хранится в параметре длины `valueMm`. Ядро копирует исходное тело. Зеркальное отражение меняет его положение; для сохранения оригинала и копии оставьте два именованных выхода либо явно объедините их. Автоматического объединения нет.

Команда `set_rotation` содержит `featureId`, `axisOriginMm`, `axisDirection`, `angleDeg`; `set_mirror_plane` — `featureId`, `planeOriginMm`, `planeNormal`. Они изменяют подходящий существующий узел с сохранением ID и зависимости. Подавление обоих модификаторов возвращает исходное тело. Команда длины `set_literal` не редактирует угол или плоскость.

Начало должно быть конечным в пределах ±10 000 мм. Компоненты направления ограничены ±1 000 000, длина вектора не меньше 10⁻⁹. Угол конечный в пределах ±360°. Ноль и полный оборот допустимы для явного повторяющегося построения. Неверные векторы, тип исходника, отсутствующие/будущие зависимости и неизвестные поля отклоняются до worker. C++ независимо проверяет аргументы с кодом `INVALID_TRANSFORM`; обычная граница структурных ошибок показывает отказ, сохраняя технические подробности.

## Выполнение, хранение и проверка

CAD IR валидирует целый пакет на временной копии. Граф зависимостей перестраивает нужные ранние операции. Изолированный worker вызывает отдельные C++-модули поворота/отражения через ограниченный CXX-мост, проверяет BREP и создаёт STEP/GLB с контрольными суммами. Существующая транзакция проекта сохраняет только корректный результат. Документ, ID и числа сохраняются в ревизиях и полном CADPACK. STEP сохраняет геометрию, но не историю преобразований. Предпросмотр или отклонённый пакет не меняет исходный документ.

`tests/rigid_transforms.rs` проверяет аналитические объём/площадь блока, AABB восьми углов по формуле Родрига, произвольные нормализуемые оси, смещённое начало, реальное зеркальное положение точным пересечением, подавление, откат пакета, неверные типы, NaN/бесконечности/почти нулевые/чрезмерные векторы и границы угла. Ожидаемый объём 16-зубой шестерни получен независимым интегрированием перекрытия диска и зуба, а не сравнением ядра с самим собой. Повторное чтение STEP должно сохранять объём, площадь, габариты, число граней и рёбер.

Это не выражения углов, редактируемые параметрические массивы, постоянные ссылки произвольных граней/рёбер, независимые компоненты импортированной сборки или оставшиеся сложные операции. Проверки релиза на других ОС и авторизованных внешних AI остаются отдельными критериями. См. [команды](command-api.md), [моделирование](modeling.md), [просмотр AI](ai-candidate-review.md), [архитектуру](architecture.md).
## Вращение замкнутого профиля

`revolve` строит нативное BREP-тело из решённого профиля `sketch2d`, включая внутренние замкнутые контуры. Добавьте операцию и назначьте выход тела одним подготовленным пакетом команд:

```json
{"type":"revolve","sketchId":"profile","axisOriginMm":[0,0,0],"axisDirection":[0,0,1],"angleDeg":360}
```

Профиль может лежать в XY, XZ или YZ. Начало мировой оси задаётся в миллиметрах, направление безразмерно. Ось должна лежать в плоскости профиля. Контур может касаться оси, но не пересекать её; отверстия становятся внутренними полостями вращения. Угол со знаком ненулевой, в пределах ±360 градусов. Начальный маршрут принимает многоугольные профили `sketch2d`, а не неявные rectangle/circle или дуги/сплайны. Прямоугольник в XZ с радиусами 2–6 мм и высотой 10 мм создаёт кольцо объёмом 320π мм³; угол 90° даёт четверть этого объёма.

`set_revolution` изменяет `featureId`, `axisOriginMm`, `axisDirection`, `angleDeg`, сохраняя зависимость от эскиза и идентификатор операции. Углы и направления не являются параметрами длины. Подавление с передачей исходного тела для этой создающей тело операции не предусмотрено. Предпросмотр и отклонённые пакеты не меняют сохранённый проект. Ревизии и полный CADPACK хранят исходный профиль, ось и угол; STEP сохраняет только полученную геометрию.

Общий ограниченный конструктор грани обслуживает выдавливание и вращение. Rust проверяет поля и тип профиля; C++ независимо проверяет принадлежность оси плоскости и пересечение оси, затем OCCT проверяет BREP перед публикацией STEP/GLB. Ошибки проходят структурированную границу `INVALID_REVOLUTION`. `tests/revolution.rs` независимо проверяет аналитические объём/площадь кольца с внутренней полостью, три плоскости, оба знака полного оборота, четверть оборота, повторное чтение STEP, откат, неверные оси/углы/типы и артефакты изолированного worker. `tests/sketch_profiles.rs` проверяет отверстия выдавливания после выделения общего конструктора. Sweep, loft, shell, кривые, независимые компоненты импортированной сборки и общая устойчивая топология остаются отдельными требованиями паритета.

См. [операции поверх импортированного STEP](imported-step-features.md): проверяемый контракт источника, хранение и ограничения редактирования.
