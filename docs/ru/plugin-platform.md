# Платформа плагинов FormaCAD

[Документация](index.md) · [English](../en/plugin-platform.md)

Статус: **среда плагинов в CAD реализована** (установка из файла, выполнение, права, UI — см. [Плагины](plugins.md) и [руководство автора](plugin-authoring.md)); каталог `plugins.formacad.ru` строится отдельно, ключ каталога в CAD — заглушка. Этот документ — общий контракт для трёх частей, которые строятся параллельно: среды плагинов в CAD, каталога `plugins.formacad.ru` и инструментов автора. Каталог открывается для всех только после того, как CAD умеет устанавливать и запускать плагины. Версия контракта — `plugin-api 0.1`; до первой публичной версии поля могут меняться, после — только совместимо (см. «Версии и совместимость»).

Опирается на [общий план 2.x](../architecture-2.0.md), раздел 8.3 «Lua and WASM extension lifecycle» и этапы 2.12–2.13.

## 1. Что такое плагин

Плагин — это WebAssembly-модуль с манифестом, упакованный в архив `.cadplugin`. Он выполняется внутри CAD в песочнице **Wasmtime** и не получает прямого доступа к файлам, сети, процессам и ОС. Всё, что плагин может сделать, идёт через функции хоста, каждая из которых требует объявленного в манифесте и подтверждённого пользователем права.

Плагин может добавлять (поле `contributes` манифеста):

| Вклад | Что это для пользователя | Как применяется |
| --- | --- | --- |
| `features` | Новые параметрические операции: шестерня, резьба, профиль… | Плагин по параметрам возвращает операции CAD IR; ядро строит геометрию. Документ хранит ID плагина, закреплённую версию, параметры и последнюю корректную геометрию |
| `commands` | Команды и действия в меню и палитре | Команда формирует план изменений через Command API; применяется одной транзакцией с откатом |
| `importers` / `exporters` | Новые форматы файлов | Получает/отдаёт байты только выбранного пользователем файла; результат импорта — CAD IR |
| `panels` / `settings` | Панели и настройки | Декларативная схема UI; CAD сам рисует её своими компонентами в обеих темах и с доступностью. Произвольный HTML/JS/CSS запрещён |

Плагин не может: читать произвольные пути, запускать программы, открывать сокеты, менять модель в обход Command API, рисовать свой HTML, работать после закрытия проекта.

## 2. Пакет `.cadplugin`

ZIP-архив, ограничения проверяются до распаковки: не больше 20 МБ сжатого и 60 МБ распакованного, не больше 200 файлов, глубина путей ≤ 6, только относительные пути без `..`, без symlink.

```text
manifest.json        обязательный, UTF-8
plugin.wasm          обязательный, точка входа (имя задаёт manifest.entry)
icon.png             необязательно, 256×256, если не используется встроенная иконка
locales/ru.json      необязательно, переводы строк плагина
locales/en.json
assets/…             необязательно, данные, которые плагин читает через host API
```

Скриншоты и README в пакет **не** кладутся: каталог берёт их из репозитория (раздел 6).

## 3. `manifest.json`

Формальная схема: [`docs/schemas/plugin-manifest.schema.json`](../schemas/plugin-manifest.schema.json), пример: [`docs/schemas/plugin-manifest.example.json`](../schemas/plugin-manifest.example.json).

| Поле | Обяз. | Описание |
| --- | --- | --- |
| `id` | да | Уникальный ID: `^[a-z0-9]+(?:-[a-z0-9]+)*$`, 3–64 символа. Закрепляется за автором при первой публикации и не меняется |
| `name` | да | Название, до 50 символов |
| `version` | да | SemVer `MAJOR.MINOR.PATCH`; должен совпадать с тегом релиза `vX.Y.Z` |
| `description` | да | Одна строка до 140 символов — подзаголовок в каталоге |
| `about` | нет | Подробное описание до 1000 символов — блок «О плагине» |
| `highlights` | нет | До 4 плашек под «О плагине»: `{ "icon": "<lucide-имя>", "label": "…" }` |
| `categories` | да | 1–3 значения из фиксированного списка (раздел 7) |
| `author` | да | `{ "name": "…", "github": "<login>" }`; `github` должен совпадать с владельцем установки GitHub App (раздел 5) |
| `repository` | да | `https://github.com/<owner>/<repo>` |
| `license` | да | SPDX-идентификатор (`MIT`, `Apache-2.0`, …) |
| `icon` | нет | Встроенная иконка `lucide:<имя>` или путь к PNG в пакете; цвет фона плашки — `iconColor` (`#rrggbb`) |
| `screenshots` | нет | До 8: `{ "src": "<путь в репозитории>", "caption": "…", "theme": "light" \| "dark" \| "any" }`; PNG/WebP/JPEG, до 2 МБ, ширина 800–2400 px |
| `minAppVersion` | да | Минимальная версия FormaCAD (`2.12.0`) |
| `api` | да | Версия контракта плагинов (`0.1`) |
| `entry` | да | Имя WASM-файла в пакете |
| `permissions` | да | Список прав (раздел 4); пустой список допустим |
| `contributes` | да | Что добавляет плагин (раздел 1); хотя бы один вклад |
| `links` | нет | `{ "homepage", "funding", "issues" }` — только `https://` |
| `locales` | нет | Языки, для которых в пакете есть переводы |

Строки манифеста — авторский контент и не переводятся CAD. Переводы плагина лежат в `locales/*.json` и подставляются по ключам `%key%`.

## 4. Права

Права объявляются в манифесте, показываются пользователю при установке и действуют только после подтверждения. Плагин без права не может вызвать соответствующую функцию хоста — это проверяется при загрузке модуля: импорт функции хоста без объявленного права отклоняет установку.

| Право | Что даёт |
| --- | --- |
| `model.read` | Читать текущую модель: параметры, операции, тела, измерения |
| `model.write` | Предлагать изменения через Command API (применяются транзакцией, видны в истории) |
| `selection.read` | Читать текущий выбор граней/рёбер/тел |
| `file.import` | Получать байты файла, который пользователь сам выбрал в диалоге импорта |
| `file.export` | Отдавать байты для файла, путь которого выбрал пользователь |
| `storage` | Своё хранилище до 10 МБ внутри профиля CAD |
| `network:<host>` | HTTPS-запросы только к указанному хосту; каждый хост — отдельное право |
| `notifications` | Показывать уведомления CAD |

Если новая версия просит **новые** права, CAD не обновляет плагин молча: показывает разницу и ждёт подтверждения. Плагин остаётся на прежней версии, пока пользователь не согласится.

## 5. Публикация: только с GitHub

Источник правды — GitHub-репозиторий автора. Загружать файлы на сайт вручную нельзя.

1. Автор входит на `plugins.formacad.ru` любым способом входа FormaCAD; для публикации нужен привязанный GitHub.
2. Автор устанавливает GitHub App **FormaCAD Plugins** на репозиторий. Установка доказывает доступ к репозиторию (работает и для организаций) и подписывает нас на события релизов. Проверки по совпадению ника недостаточно и она не используется.
3. Автор нажимает «Опубликовать» и выбирает репозиторий. Сервер проверяет, что установка App принадлежит привязанному GitHub-аккаунту автора и `manifest.author.github` совпадает с ним.
4. Автор делает релиз с тегом `vX.Y.Z` и прикрепляет `<id>-<version>.cadplugin`.
5. По событию `release.published` (резерв — опрос раз в час) сервер:
   - скачивает пакет и проверяет лимиты архива, схему манифеста, `version == tag`, `id` закреплён за этим автором;
   - проверяет WASM: валидный модуль, импортирует только функции хоста `formacad:plugin@0.1`, каждый импорт покрыт объявленным правом, нет WASI-доступа к ФС/сети;
   - считает SHA-256, **хранит собственную копию** пакета и копирует скриншоты к себе (GitHub из России доступен нестабильно; пользователи скачивают только с нашего сервера);
   - берёт README из репозитория, очищает Markdown (без сырого HTML, картинки — только с нашего прокси);
   - подписывает запись индекса ключом каталога (Ed25519, отдельный от ключей токенов и прав) и **публикует автоматически**.
6. Версию с ошибкой проверки не публикует; автор видит причину в кабинете.

Модерация — автоматическая (решение владельца). Защита от угона аккаунта автора: новые права требуют повторного согласия в CAD; администратор может **отозвать** версию или плагин (yank/delist) — CAD предупреждает установивших и не ставит отозванную версию; кнопка «Пожаловаться» на странице плагина.

## 6. Каталог `plugins.formacad.ru`

Внешний вид — по образцу каталога Obsidian, в стиле FormaCAD, RU/EN, две темы.

- **Главная:** поиск, «Популярные / Новые / Обновлённые», категории с количеством.
- **Страница плагина:** иконка, название, автор с аватаром GitHub (ссылка на профиль), число установок; кнопка «Добавить в FormaCAD» и меню «…» (GitHub, сообщить об ошибке, предложить функцию, пожаловаться); карусель скриншотов (для текущей темы, если указан `theme`); вкладки «Обзор» (README свёрнут с плавным «Показать ещё»), «Проверки», «Обновления» (список релизов с заметками).
- **Боковая колонка:** «Состояние» (по GitHub: последний коммит, частота релизов, реакция на issues — честные метрики, без выдуманных оценок), «Проверки» (манифест, WASM, хеш, запрошенные права), «О плагине» + плашки `highlights`, «Сведения» (версия, обновлён, создан, число релизов, установки, совместим с FormaCAD X+, лицензия), «Права», «Автор».
- **Профиль автора:** аватар, имя, логин и био из GitHub, ссылки на соцсети (из GitHub `social_accounts` и добавленные на сайте, только `https://`), список его плагинов.

Вход на `plugins.formacad.ru` — через сервер аккаунтов `formacad.ru` по OAuth 2.0 с PKCE (каталог — отдельный клиент, как CAD). Отдельные пароли и cookie между доменами не используются.

## 7. Категории

Фиксированный список (переводится CAD и каталогом): `modeling` — моделирование, `sketching` — эскизы, `import-export` — форматы, `measurement` — измерения и анализ, `manufacturing` — производство и печать, `automation` — автоматизация, `ai` — AI, `ui` — интерфейс, `library` — библиотеки деталей, `other` — другое.

## 8. Установка в CAD

1. Кнопка «Добавить в FormaCAD» открывает `formacad://plugins/install?id=<id>&version=<version>`.
2. CAD получает подписанную запись индекса с `https://plugins.formacad.ru/api/v1/plugins/<id>/versions/<version>`, проверяет подпись ключом каталога, встроенным в приложение, скачивает пакет **с нашего сервера** и сверяет SHA-256.
3. Показывает окно: название, автор, версия, права простыми словами, ссылка на страницу. Ничего не устанавливается без нажатия «Установить».
4. Пакет распаковывается в профиль CAD (`plugins/<id>/<version>/`); несколько версий могут сосуществовать; проект закрепляет используемую версию.
5. Без сети установленные плагины работают; без каталога — тоже. Ссылки `formacad://` без подтверждения никогда ничего не выполняют.

## 9. Выполнение

Wasmtime с ограничениями: топливо (fuel) на вызов, память до 256 МБ на экземпляр, время вызова до 10 с (настраивается для операций), прерывание без закрытия CAD. Ошибка плагина откатывает его транзакцию и показывается как ошибка плагина, а не CAD. Журнал вызовов — локально, без отправки.

Если плагина нет или он отключён: тело, созданное его операцией, видно, измеряется и экспортируется по последней корректной геометрии, но операция и зависимое перестроение заблокированы до установки нужной версии.

## 10. Версии и совместимость

`api` — MAJOR.MINOR контракта. MINOR добавляет функции хоста и поля совместимо; MAJOR ломает. CAD поддерживает текущий MAJOR и объявляет устаревание за один выпуск. Схема параметров операции плагина версионируется вместе с плагином; при обновлении проекта параметры мигрируют после резервной копии и проверки сборки.

## 11. Интерфейс хоста `formacad:plugin@0.1`

WIT-файл: [`docs/plugin-api/wit/formacad-plugin.wit`](../plugin-api/wit/formacad-plugin.wit). Плагин — **WebAssembly-компонент** (component model), а не core-модуль: WIT описывает типы точно, каждая группа функций хоста — отдельный интерфейс, и права проверяются по списку импортов компонента без разбора ABI. Компонент импортирует только те интерфейсы, которые реально вызывает.

| Интерфейс | Право | Функции |
| --- | --- | --- |
| `types`, `log`, `assets` | не нужно | типы ошибок; запись в локальный журнал; чтение файлов своего пакета (`assets/`, `locales/`) |
| `model` | `model.read` | `document()` — CAD IR v2 текущей ревизии (JSON) |
| `selection` | `selection.read` | `current()` — выбор во viewport (JSON) |
| `storage` | `storage` | `get/set/remove/keys`, всего до 10 МБ |
| `notifications` | `notifications` | `notify(level, message)`, до 5 за вызов |
| `network` | `network:<host>` | `fetch(request)` — только HTTPS к объявленным хостам, без редиректов, 15 с, ответ до 10 МБ |

Экспорты плагина и требования к правам:

| Экспорт | Вклад | Право | Результат |
| --- | --- | --- | --- |
| `feature.build(id, params, context)` | `features` | `model.write` | JSON-массив команд Command API |
| `command.run(id, params, context)` | `commands` | `model.write` | `{"message","commands":[…]}` |
| `importer.import-file(id, name, bytes, params, context)` | `importers` | `file.import` | JSON-массив команд |
| `exporter.export-file(id, document, params, context)` | `exporters` | `file.export` и `model.read` | байты файла |
| `panel.render(id, context)` | `panels` | — | декларативное представление `{"blocks":[…]}` |

CAD IR, параметры и команды передаются строками JSON и разбираются хостом теми же строгими типами, что и собственный Command API: WIT остаётся стабильным, пока CAD IR растёт. `context` содержит `api`, `locale`, `revisionId`, `settings` и `idPrefix`; все новые ID (операции, тела, параметры) обязаны начинаться с `idPrefix`, иначе результат отклоняется.

## 12. Уточнения реализации 0.1

- **Пакет:** допускаются только `manifest.json`, файл `entry`, иконка, `locales/*.json`, `assets/**`; сжатие — stored/deflate; одинаковые пути без учёта регистра запрещены.
- **Запись индекса каталога** (`GET /api/v1/plugins/<id>/versions/<version>`): `{"payload":"<base64 JSON>","signature":"<base64 Ed25519 над байтами payload>","keyId":"…"}`. В payload: `format: "formacad-plugin-index-entry/1"`, `id`, `version`, `name`, `permissions`, `sha256`, `size`, `downloadUrl`, `pageUrl` (оба `https://plugins.formacad.ru/…`), `yanked`. CAD сверяет id/version со ссылкой, размер и SHA-256 пакета, а права в манифесте — с подписанным списком. Неизвестные поля игнорируются.
- **Ключ каталога** встроен в `apps/desktop/src-tauri/src/plugins/catalog/keys.rs`; пока список пуст (TODO владельца), установка из каталога отвечает `PLUGIN_CATALOG_KEY_MISSING`, установка из файла работает.
- **Операция плагина** сохраняется как обычные операции CAD IR (`add_feature`/`add_body`) одной ревизией; в истории видна подпись «Плагин <имя> <версия>: <операция>». Поэтому тело видно, измеряется и экспортируется без плагина. Повторное открытие операции с параметрами плагина и закрепление версии в документе **не реализованы**: для этого нужен новый тип операции CAD IR с поддержкой в worker (предложение: `pluginFeature { pluginId, version, featureId, params, expanded }`).
- **Панели** открываются из палитры команд окном, а не в боковой колонке/инспекторе; форма панели отправляет команду плагина, параметры которой совпадают с полями формы.
- **Ссылки `formacad://`** при уже запущенном CAD на Windows открывают второе окно (single-instance не подключён, чтобы не менять поведение запуска нескольких окон и отдельных профилей).
- **Смена активной версии** с новыми правами из настроек не выполняется: нужно установить эту версию заново (окно согласия).

## 13. Что пока не решено

- Подпись пакетов самим автором (сейчас целостность обеспечивают хеш и подпись индекса каталогом).
- Платные плагины — не планируются.

## Проверка

Документ проверяется `npm run check:docs`. Схема манифеста — JSON Schema draft 2020-12; пример манифеста должен ей соответствовать (будет проверяться тестом при появлении кода).
