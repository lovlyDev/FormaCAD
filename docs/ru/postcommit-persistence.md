# Сохранение после durable commit

Метаданные проекта и история сохраняются в одной SQLite-транзакции. До её commit отказ валидации, доступа, истории или подготовки хранения остаётся ошибкой. Неизменяемые staging-файлы, записанные до неудачного commit, могут остаться без ссылки; очистка временной папки построения модели их не удаляет.

После успешного SQL commit ревизия уже сохранена. Публикация манифеста папки может независимо завершиться ошибкой. Журнал хранения и неизменяемое поколение остаются доступными для восстановления при следующем открытии проекта; приложение возвращает сохранённый проект и не сообщает об отказе изменения модели. Отмена после этой границы не откатывает сохранённую ревизию.

## Зеркала и защита путей

`projects/mirrors.rs` обновляет `project.json`, `workspace/model.py` и `workspace/model.parameters.json` после durable commit. Это удобные зеркала; SQLite и проверенное поколение хранения остаются основными источниками данных. Название файла исходника сохраняет прежнее соглашение совместимости, в том числе для типизированного CAD-документа.

Каждый путь зеркала по-прежнему проходит `security::guarded`. Отсутствующая корневая папка, запрещённая символическая ссылка, ошибка сериализации, записи или переименования создаёт диагностическое предупреждение. Запрещённый путь пропускается; приложение не повторяет запись без защиты. Отказ одного зеркала не мешает попыткам обновить остальные. Ошибки зеркал не удаляют поколения хранения, не очищают журнал незавершённой публикации и не возвращают израсходованное разрешение.

Перед публикацией манифеста путь проекта повторно проверяется относительно корневой папки приложения. Пути зеркал тоже проверяются относительно неё, включая саму папку проекта. Отказ проверки пути публикации сохраняет recovery journal. Эти проверки не означают наличие системной capability, исключающей любую гонку с конкурентной заменой файловых путей.

## Уведомления о ревизии

Прежнее событие `project://revision-created` соответствует сохранённому изменению указателя текущей ревизии. Поэтому оно продолжает уведомлять существующих потребителей об undo и redo, несмотря на историческое название. Сохранение сообщений, названия проекта или других метаданных с тем же указателем ревизии не создаёт дополнительного уведомления.

Host применения модели сохраняет проект без application handle, а IPC-обёртка один раз публикует сохранённый результат. Последующее сохранение сообщения AI-ассистента не повторяет событие. Неизменённая модель и отказ применения не создают уведомления о ревизии. Это решение backend о событии; проверка чистого условия или SQL-транзакции не подтверждает доставку внутри установленного WebView.

## Маршрут проверки

Unit fixture использует временные SQLite и управляемые папки проекта. Закрытый callback, компилируемый только для unit tests, временно перемещает собственную папку поколений сразу после настоящего SQL commit, вызывая отказ публикации. Проверки требуют сохранённых head и истории, сохранённого recovery journal и успешного настоящего восстановления после возвращения только этой fixture-папки поколений. Затем реальное сохранение метаданных сообщения ассистента должно сохранить список ревизий и единственную запись history edit. Отдельные проверки условия события покрывают начальный пустой проект, новый head, неизменённые метаданные, undo и redo.

Независимый сбой только зеркал заменяет временную папку workspace на junction (Windows) или символическую ссылку (Unix) к другой временной папке после успешной публикации манифеста и до обновления зеркал. Проверяется сохранность внешнего контрольного исходника и отсутствие записи зеркала параметров по внешнему пути. Проверка требует успешного сохранённого результата, уже опубликованного поколения с новым head и отсутствия pending journal. Это отличает отказ защищённого зеркала от ошибки публикации.

Callbacks относятся к одному запросу и отсутствуют в production-структуре hook. IPC не принимает исполняемый файл worker, callback или произвольный путь вывода проекта. Эти тесты проверяют семантику хранения, но не доказывают геометрическую корректность, восстановление при любых сбоях или установленную работу на всех платформах.
