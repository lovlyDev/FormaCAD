# Доступ к проекту в сеансе

[Документация](index.md) · [English](../en/project-access.md) · [Хранилище папок](project-storage-v2.md)

Открытие индексированного проекта вызывает `acquire_project_access(projectId)`. Удерживаемая приложением OS-блокировка даёт режим `write`; другой процесс получает `read_only` и PID владельца, если он доступен. `project_access_status` возвращает `write`, `read_only` либо `closed`. Закрытие вызывает `release_project_access`; активная задача проекта возвращает `PROJECT_ACCESS_BUSY`. Завершение процесса освобождает блокировку средствами ОС. После закрытия другого владельца доступ нужно запросить повторно: read-only сеанс не становится писателем самовольно.

`AppState.project_access` хранит отдельный реестр экземпляра приложения. Постоянные файлы блокировок находятся в управляемом корне `.project-access/<UUID проекта>.lock` и никогда не удаляются и не перехватываются принудительно. PID, время получения и случайный ID сеанса описывают владельца; право записи определяет OS lock. Обычный список и чтение проектов не создают сеансов. Сохранение неоткрытого проекта использует временный lease до завершения операции, поэтому обновление карточек не блокирует все проекты. Вложенные операции разделяют guard `Arc<File>`. Применение CAD, конвертация STEP и выполнение AI держат guard всю задачу. Сохранение, удаление и разрешения изменения проверяют право записи в Rust до изменений; отключение подтверждений не отменяет read-only.

Read-only сеанс может просматривать сохранённые данные и экспортировать mesh/пакеты. Экспорт STEP читает неизменяемые файлы либо строит выбранную геометрию в отдельной `.transient` папке и сохраняет в выбранное пользователем место; `cache` и `output` проекта не меняются. Читатель может просматривать проверенное поколение из SQL-журнала, пока другой владелец завершает публикацию папки, но не публикует его и не очищает журнал. Временные папки экспорта удаляются после завершения; аварийное завершение может оставить неиспользуемые временные файлы.

`copy_project_for_editing(projectId)` захватывает сохранённые данные проекта и логическую историю, материализует неизменяемые вложения и сохраняет новый UUID проекта. ID ревизий и история сохраняются. Исходник не меняется, включая read-only и прежнее хранение через базу. Машинные настройки, разрешения и учётные данные CLI не копируются. Копия получает постоянное право записи при открытии; само создание копии не удерживает lease.

Реализация координирует процессы с одним управляемым корнем проектов. Редактирование внешней папки на месте, распределённые/cloud-блокировки, heartbeat, принудительное снятие и гарантия согласованности NAS пока не реализованы. UI получает доступ до включения редакторов и освобождает его при навигации; backend остаётся окончательной границей проверки.

Изолированные тесты `src/project_access/tests.rs` проверяют два реестра, реальный второй процесс и принудительное завершение владельца, отказ read-only сохранения до изменения индекса и файлов, проверку разрешений до записи аудита, освобождение временных/вложенных leases и создание копии без изменения исходника. Используются временные папки и тестовая SQLite, пользовательская AppData не затрагивается.

Проверка Windows: 6 основных тестов прошли в `.local/native-access-2.0-final.log`. Седьмой helper помечен ignored для обычного запуска, но реальный тест второго процесса отдельно запускает его и принудительно завершает владельца. PID читается из отдельного ограниченного `.owner.json`, поскольку Windows не позволяет читать диапазон под exclusive lock.

## Интерфейс и переключение

В режиме чтения рабочее место показывает причину ограничения, «Повторить запрос доступа» и «Сохранить редактируемую копию». Просмотр, выбор и измерения остаются доступны; изменение модели, undo/redo и AI-запросы блокируются. Копия получает новый UUID и переносимую историю; исходник не меняется. Переход к другому проекту доступен. Модуль `features/project-access` последовательно выполняет IPC открытия/закрытия: отложенное освобождение на 250 мс предотвращает потерю блокировки при StrictMode, повторное получение ставится после уже начатого освобождения. Ошибка освобождения не скрывается. Окончательная защита находится в backend, а не в состоянии кнопок.

## Чистое чтение для копии и экспорта

Копирование текущего управляемого проекта и экспорт `.cadpack` используют [общий снимок проекта и истории](project-snapshots.md) из одного SQL-снимка, с проверкой файловой генерации и повторной проверкой после чтения вложений перед публикацией. Эти операции не вызывают неявное восстановление исходника. Если требуется восстановление, откройте проект заново и повторите операцию. Измерения сохраняют прежние совместимые коды ошибок. Сохранение новой копии записывает новый проект в общую SQLite; исходный проект остаётся прежним, но весь файл базы не обязан оставаться побайтово одинаковым. Это изменение управляемого backend, а не открытие внешней папки на месте или конверсия истории настоящего проекта 1.1.
