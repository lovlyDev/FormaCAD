# Хранилище папок проекта v2

[Документация](index.md) · [English](../en/project-storage-v2.md) · [Архитектура](architecture.md)

Локальный backend теперь сохраняет проверяемую самодостаточную папку проекта. Это отдельная версия **формата хранилища** `storageVersion: 2`; совместимый `Project.schemaVersion: 1` и CAD IR v2 не переименовываются. Формат не означает готовность приложения 2.0.

## Состав и перенос

В папке находятся `manifest.json`, `assets/<sha256>`, `metadata/generations/<uuid>/project.json` и `history.json`. Manifest указывает активное поколение и содержит явный список файлов, размеры и SHA-256. `project.json` включает неизменяемые ревизии, текущую ревизию, исходники CAD, сообщения, метаданные и список вложений. `history.json` сохраняет логический курсор undo/redo и журнал переходов. Учётные данные, разрешения CLI и машинные настройки не переносятся.

Файлы модели лежат в локальном CAS `assets`, а не только в глобальной `.blobs`. Повторные сохранения переписки, названия и миниатюры не копируют крупные вложения: поколения ссылаются на один неизменяемый файл с хешем. Контрольная сумма проверяется при чтении. Простое копирование всей папки сохраняет данные, необходимые для открытия, без исходной базы SQLite и глобального кэша. Служебные старые `attachments`, `output`, `workspace` и `.blobs` остаются для совместимости; пользовательские данные не удаляются.

Backend `projects::import_folder` читает выбранную абсолютную папку, проверяет все объявленные файлы и создаёт локальную индексированную копию. Исходная папка открывается только для чтения. Совпадение ID с уже известным проектом возвращает конфликт; явный `save_copy` назначает новый ID проекта, сохраняя ID ревизий и курсор undo/redo. Это импорт копии, а не редактирование внешней папки на месте. Явный IPC-маршрут: `project_storage_v2::ipc::inspect_project_folder` → просмотр → `import_project_folder`. Нативный выбор папки возвращает название, ID, число ревизий, наличие ID в индексе и SHA-256 manifest, использованного при просмотре. Импорт проверяет именно этот manifest, затем читает его поколение и историю команд. Изменившийся источник возвращает `PROJECT_FOLDER_CHANGED`, не меняя источник или индекс. Байты вложений и истории повторно проверяются при материализации. `saveCopy` явно определяет обработку совпадения ID. Нативное окно использует имя продукта `Forma CAD`; надписи просмотра и ошибки переводятся на границе UI. Копия создаётся в управляемом корне проектов; это не выбор нового корня хранения и не получение постоянной блокировки внешней папки.

## Атомарное сохранение и восстановление

1. Процесс получает OS advisory lock `metadata/storage-v2.lock`. Второй писатель отклоняется; завершение процесса освобождает блокировку без удаления файла другого владельца. В файле записаны PID и время получения.
2. Вложения проверяются и сохраняются в CAS; новое поколение метаданных записывается через `create_new` и `sync_all`. Неполное поколение не видно через активный manifest.
3. Одна SQL-транзакция сохраняет индекс проекта, undo/redo, журнал действий и запись `project_storage_commits`: исходный хеш manifest, целевой manifest и хеш payload.
4. После SQL commit активный manifest атомарно заменяется через временный файл. Предыдущий проверенный manifest сохраняется в `metadata/manifest.previous.json`.
5. После публикации запись pending commit удаляется. Если процесс оборвался после SQL commit, следующее чтение завершает **только зарегистрированное** поколение. Изменённый извне manifest, несовпадающий payload или повреждённый файл вызывают ошибку, а не скрытую перезапись.

Повреждённый активный снимок можно отдельно проверить через `read_backup`. Backend не подменяет текущую модель старой резервной копией автоматически. Ошибка до SQL commit оставляет прежнее поколение активным. Ошибка публикации после SQL commit сохраняет журнал завершения; нельзя повторять действие как будто оно не было сохранено.

При первом сохранении прежнего проекта исходный payload материализуется в проверенное базовое поколение до перехода. Исходная SQLite запись и старые файлы не удаляются. Это совместимая упаковка существующего документного состояния, а не восстановление отсутствующей истории операций у STEP/STL или параметрическое преобразование проектов 1.1.

## Ограничения и защита

Manifest отклоняет неизвестные поля/версии, повторные пути, traversal, символические ссылки и небезопасные хеши. Каждый файл не превышает установленный лимит: вложение 40 MiB, метаданные 32 MiB, командная история 16 MiB; суммарный manifest ограничен 148 MiB. Необъявленные файлы не импортируются. Сохраняются все необходимые вложения; выборочное исключение личных данных пока не реализовано.

SQLite пока остаётся совместимым индексом и частью локального протокола транзакции. Независимость папки доказана для чтения и импорта копии; редактирование непосредственно на NAS/USB, heartbeat, локальные черновики при потере носителя и полный выбор формата по SSD/NAS benchmarks ещё требуют отдельной реализации. Блокировка ОС не гарантирует согласованность облачно синхронизируемой папки. Вложения не размножаются при metadata-only saves, но проверка их хешей требует чтения; инкрементальный кэш проверок ещё не введён. Старые поколения и бесхозные staging файлы не удаляются автоматически: безопасная политика retention/GC пока не реализована. `sync_all` и atomic rename не объявляются гарантией от аппаратной потери питания на каждой файловой системе.

## Проверка

[Изолированные тесты](../../apps/desktop/src-tauri/src/project_storage_v2/tests.rs) используют только временные папки и тестовую SQLite: перенос без глобальной базы/кэша; повторное использование CAS; crash между SQL и manifest; конфликт внешнего изменения; повреждение активного поколения и читаемость backup; некорректные пути/версии/лимиты; ошибка миграции вложения; блокировка и освобождение; импорт с конфликтом ID и сохранением исходника. Отдельные тесты истории проверяют portable cursor и журнал. Пользовательская AppData, установка и GitHub для этих проверок не используются.

[Доступ в сеансе](project-access.md) описывает постоянное владение в общем корне и создание копии из read-only.
