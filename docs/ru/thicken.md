# Утолщение выбранной грани

[Документация](index.md) · [English](../en/thicken.md) · [M4](modeling-ii.md)

## Назначение и действия

Операция создаёт отдельное твёрдое тело из одной явно выбранной CAD-грани. Исходное тело остаётся в проекте без изменения геометрии и источника. Это отличается от оболочки, которая удаляет выбранные грани исходного солида и оставляет полость.

Откройте авторскую модель, включите выбор граней и выберите нужную грань в 3D-виде. В меню «Инструменты» выберите «Утолщить грань». Диалог показывает ID тела и точную роль грани: автоматического выбора первой грани нет.

Введите толщину со знаком в миллиметрах. Положительное значение следует ориентированной нормали грани, отрицательное направлено в обратную сторону. Проверьте настоящий 3D-предпросмотр и нажмите «Построить», затем подтвердите разрешение. Пустое поле и нулевая толщина блокируют построение. «Отмена» не создаёт ревизию. После применения используйте обычные Undo/redo: это явные операции истории.

## Технический маршрут

features/thicken захватывает проект, ревизию, тело и копию TopologyReference. Изменение проекта, ревизии или маршрута ссылки делает захват недействительным; операция не переносится на другое тело. Предпросмотр проверяет тот же документ, который описывает пакет add_feature + add_body.

apply_ir_commands проверяет expectedRevision и работает со staged-копией. CAD IR ThickenFace содержит bodyFeatureId, reference и offset (literal либо параметр). Rust native/thicken.rs вызывает отдельный cad-core/src/thicken.cpp. OCCT разрешает точную ссылку, копирует выбранную грань и выполняет MakeThickSolidBySimple. Результат должен быть одним замкнутым солидом: OrientClosedSolid задаёт ориентацию, общая checked-проверка контролирует BREP, конечные положительные объём и площадь. Исходная геометрия не редактируется.

Новый feature и новое тело публикуются одной ревизией только после успешного завершения worker. Неподдерживаемая, устаревшая или неоднозначная ссылка отклоняется. Некорректная толщина и невозможное геометрическое утолщение дают переведённую ошибку с отдельными техническими подробностями.

## Хранение и история

Операция сохраняется в CAD IR текущей ревизии, вместе с исходными зависимостями и новым телом. Используется существующий формат проекта; SQL-миграций нет. Тела не объединяются автоматически. При отрицательной толщине новое тело может находиться внутри исходного: суммарные измерения сборки складывают объёмы тел и не означают объём их булева объединения.

Утолщение является генератором нового тела. Pass-through подавление, которое подставило бы целый исходный солид вместо пластины, запрещено. Изменение истории требует отдельной команды. Ошибка staged-операции оставляет прежний снимок проекта.

## Геометрические проверки

Брусок 40×20×10 мм: верхняя грань при ±2 мм даёт пластину 40×20×2 мм, объём 1600 мм³, площадь 1840 мм², 6 граней. Положительное смещение даёт Z=10…12, отрицательное — Z=8…10. Нижняя грань при +2 мм даёт Z=−2…0. Исходник сохраняет 8000 мм³.

Боковая грань цилиндра R10/H20 при +2 мм даёт 880π мм³ и 968π мм²; при −2 мм — 720π мм³ и 792π мм². У каждой втулки 4 грани. Проверены STEP round-trip, BREP-валидность, площадь и объём; схлопывание при −12 мм, ноль, NaN, превышение лимита и неверные ссылки отклоняются.

Rust/worker-тест проверил атомарное добавление тела одной ревизией и полный откат при ссылке на отсутствующую в бруске цилиндрическую грань. STEP round-trip всей сборки сохранил 9600 мм³, 4640 мм², 12 граней и 24 ребра. Отдельно проверена повёрнутая грань с явным occurrence: объём 1600 мм³, толщина по повернутой нормали 2 мм.

Собранное Windows-приложение со встроенным frontend прошло настоящий UI → IPC → host → OCCT в RU/EN и обеих темах: 4/4, без ошибок JavaScript. Тестовые проекты создавались реальными native-командами, а грань выбиралась настоящим нажатием в viewport. Поле «Выбранная грань» подтвердило body · box-face:zmax. Ноль и пустое поле блокируют Build; отмена оставляет ревизию. Подтверждённое построение добавляет одну ревизию: исходник 8000 мм³, пластина 1600 мм³ / 1840 мм², сборка 9600 мм³ / 4640 мм². EN/light также проверяет −2 мм. Undo возвращает одно тело и 8000 мм³, redo — два тела и 9600 мм³; сохранённая ревизия утолщения остаётся в истории.

Повторяемый сценарий [thicken-native.mjs](../../scripts/acceptance/thicken-native.mjs) использует изолированный host/worker и CDP, подготовленные по [инструкции M4](modeling-ii.md). Из корня в PowerShell задайте $env:FORMA_NATIVE_ACCEPTANCE='isolated', затем запустите node scripts/acceptance/thicken-native.mjs http://127.0.0.1:9336 <абсолютный-путь-к-report.json>. Каталог отчёта должен существовать. Сценарий меняет только отдельный тестовый профиль, сохраняет отчёт и снимки, не подменяет IPC и не повторяет упавшие команды. При выборе точки он обходит существующий центральный манипулятор вытягивания M3, сохраняя настоящий hover по той же CAD-грани.

Проверки этапа: 278 Rust lib PASS / 2 штатных ignored; отдельный host/worker transaction PASS; 26/26 CTest; 299/299 Vitest; cargo fmt --check и строгий Clippy в native-occt и стандартной конфигурациях; lint, production build и check:i18n/docs/migrations/version PASS. Установщик не собирался.

## Ограничения

Выбирается одна грань с поддерживаемой точной топологической ссылкой. Пакеты граней и свободные оболочки не принимаются. Для импортированной или перестроенной геометрии без такого provenance команда недоступна; порядковый номер треугольника не подменяет CAD-ссылку. Самопересечения и слишком большая внутренняя толщина могут быть отклонены OCCT. Новые поверхности результата пока не получают автоматически перепривязанные именованные роли. Толщина задаётся в диалоге; отдельный F9-редактор этой операции не добавлен.

Проблемы конкурентного чтения хранилища отслеживаются отдельно в [Issue #32](https://github.com/lovlyDev/FormaCAD/issues/32#issuecomment-6825300767). Проверка после подготовки миниатюры не доказывает исправления read-after-write.

## Дробная толщина

Поле принимает произвольные конечные дробные значения в установленном диапазоне. Ранее шаг HTML-поля 0,1 мм блокировал отправку −1,25 мм, хотя предпросмотр был корректен. Теперь браузер не навязывает кратность шага; ненулевую толщину и геометрию по-прежнему проверяют Command API и OCCT. Для верхней грани 40×20 при −1,25 мм ожидаются 1000 мм³ / 1750 мм², сборка с исходником — 9000 мм³ / 4550 мм². Нативный сценарий сохраняет проверку validity, Build, истинный hover, разрешение, измерения, undo/redo. Повторная приёмка собранного приложения прошла RU/EN × dark/light: 4/4, без подмены IPC и необработанных JS-ошибок. EN/light подтвердил −1,25 мм: пластина 1000 мм³ / 1750 мм², сборка 9000 мм³ / 4550 мм², undo → 8000 мм³, redo → 9000 мм³. Остальные три сценария сохранили +2 мм и 1600 мм³ / 1840 мм². Текущие проверки: 281 Rust lib / 2 штатных ignored, 28 CTest, 309 Vitest, 71 e2e / 89 штатных skip, fmt, строгий Clippy, lint/build, i18n/docs/migrations/version — PASS. Кнопки ± используют стандартный шаг свободного числового поля 1 мм; точные дробные значения вводятся с клавиатуры.
